# 校园交易核心链路测试计划

## 目标与范围

验证注册/登录、验证码、地址所有权、下单、订单状态变更及订单沟通接口。重点使用等价类、边界值、状态迁移和并发场景发现越权、库存超卖及数据不一致问题。

### 链路

```text
申请邮箱验证码 -> 验证码注册 -> 登录
卖家发布商品 -> 买家提交本人地址下单 -> 库存扣减 -> paid
卖家发货 -> shipped -> 买卖双方沟通
```

当前应用只提供 `paid -> shipped` 发货迁移；模型中的 `completed`、`cancelled` 暂无 API 迁移端点，因此不把它们描述为已覆盖的接口行为。

## 风险及策略

| 风险 | 测试策略 | 通过条件 |
|---|---|---|
| 并发下单导致库存小于零或重复订单 | 两个独立 HTTP 会话同时购买最后一件库存 | 恰好一个请求成功；库存为零；只生成一个订单 |
| 订单状态被越权或重复变更 | 买家尝试发货；卖家发货后重复发货 | 非卖家为 403；仅允许一次 `paid -> shipped` |
| 地址/订单被其他用户读取或修改 | 使用第三方账号访问地址修改、订单消息和聊天页面 | 返回 403；数据不发生变化 |
| 验证码错配、过期、未来时间或重复使用 | 参数化邮箱、验证码和时间边界 | 注册失败且不创建用户；成功注册后验证码被消费 |
| 部分提交及错误输入 | 模拟订单提交异常；提交缺失、无效 JSON 字段 | 失败时库存/订单/消息均回滚；输入错误返回 4xx |

## 测试环境

- Python 3.10，pytest。
- API 集成用例通过 `requests` 请求本机启动的 Flask/Werkzeug HTTP 服务。
- 使用 pytest 临时目录中的 SQLite 文件数据库，以支持多线程请求；测试不会连接开发用 MySQL。
- 邮件发送使用 mock，不访问真实 SMTP。
- 每个测试前清理表数据，每个测试使用独立的 requests 会话。

## 执行方式

```powershell
conda run -n flask-env python -m pytest -q
```

可按风险筛选：

```powershell
conda run -n flask-env python -m pytest -m order -q
conda run -n flask-env python -m pytest -m security -q
conda run -n flask-env python -m pytest -m email_code -q
```

## 退出标准与限制

- 所有自动化用例通过；失败不得被忽略或标记为预期失败。
- 并发检查使用 SQLite 测试库验证原子扣减逻辑；发布前仍建议在目标 MySQL 版本上进行并发压测。
- 当前未实现订单完成/取消接口；验证码发送频率限制和邮件服务可用性不在本地自动化范围内。
